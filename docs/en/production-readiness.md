# Production readiness and homologation

[Português (Brasil)](../pt-BR/production-readiness.md)

Version 1.5.0 is the current stable release. Repository-side safety, validation, CI and security gates passed and the maintainer approved the software release on 2026-09-14.

Extended controlled hardware checks remain in progress and are tracked in [Field validation record — 1.5.0](homologation-1.5.0.md). These checks refine device-specific compatibility evidence and must not be confused with the software release gate.

## Implemented repository gates

- dedicated `sysUpTime.0` heartbeat and five-minute SNMP `nodata()` alert;
- management-agent uptime reset notice;
- standardized RFC1628 identification items plus automatic inventory links;
- read-only RFC1628 diagnostic-test results and result triggers;
- RFC1628 active alarm-table discovery with human-readable well-known alarm value map;
- RFC1628 battery current/temperature retained as optional items **disabled by default** after the reference card returned `noSuchObject` for both;
- production battery current kept on the field-observed Vertiv private `4149` object;
- private battery-temperature metric disabled by default and removed from production dashboard/alerting after returning approximately `-0.1 °C` on the reference device;
- private input-power metrics disabled by default even after scale characterization, because standardized RFC1628 true power is preferred;
- load alarms based on standardized `upsOutputPercentLoad` discovery instead of private aggregate load;
- misleading legacy graphs removed;
- real Zabbix 7 API fresh-import and in-place-upgrade tests in CI/release workflow;
- MIB/OID source provenance and compatibility matrix;
- documentation validation against current template triggers/macros/version/release policy;
- CodeQL security analysis in the release path.

## Battery field result

On the Vertiv ITA-20kVA used during development, the SNMP card implements only part of the UPS-MIB battery group. `upsBatteryStatus`, charge, runtime and voltage work, while `upsBatteryCurrent` (`.1.3.6.1.2.1.33.1.2.6.0`) and `upsBatteryTemperature` (`.1.3.6.1.2.1.33.1.2.7.0`) return `No Such Object available on this agent at this OID`.

Release 1.5.0 treats that as a card compatibility property rather than a Zabbix collection failure: both standard scalars remain available for other cards/firmwares but are disabled and trigger-free by default. No default dashboard widget depends on them.

The Vertiv private battery-current item (`vertiv.battery.current`, OID ending `4149`) has been observed working on the device and remains on the dashboard. No default battery-temperature trigger is provided until a supported and validated battery-temperature sensor/OID is available for the target device.

## History and capacity planning

The template favors operational visibility on a single UPS, with several status/battery items collected every 30 seconds and electrical values typically every minute. At scale, review Zabbix history/trend retention before linking the template to many devices.

Approximate raw samples generated by one continuously supported item are:

| Interval | Samples per day per item |
| --- | ---: |
| 30 s | 2,880 |
| 1 min | 1,440 |
| 2 min | 720 |
| 5 min | 288 |
| 15 min | 96 |
| 1 h | 24 |

The dedicated `ups.snmp.uptime` heartbeat intentionally keeps only 7 days of history and does **not** use discard-unchanged preprocessing because the five-minute `nodata()` availability trigger depends on receiving a sample every polling cycle.

## Post-release field validation procedure

The following controlled checks continue after the software release and are used to strengthen the compatibility claim for the reference hardware:

1. Confirm `ups.snmp.uptime` updates every minute and verify the five-minute availability problem/recovery in a controlled SNMP interruption.
2. Compare RFC1628 manufacturer/model/software/name with the UPS web UI and record unsupported standard objects.
3. Confirm battery status, private validated battery current, charge and runtime; keep the two unsupported RFC1628 battery scalars disabled on this card/firmware.
4. Confirm input/output/bypass discovery and per-phase `upsOutputPercentLoad`.
5. During a safe real alarm, confirm `upsAlarmTable` discovery and recovery behavior.
6. During a safe diagnostic/battery-test result transition, confirm the read-only result items/triggers. Do not initiate tests through this template.
7. Review Overview, Electrical and Battery & Environment dashboards in normal and representative incident windows.
8. Record SNMP security level and exact UPS/card/firmware/Zabbix versions.
9. Complete and sign off [the field validation record](homologation-1.5.0.md).

Completing these checks may upgrade the compatibility wording for that exact hardware combination to **field-homologated**. Until then, the release remains stable software with explicitly limited device-specific certification wording.

## Non-blocking optional features

Vertiv-specific trap parsing is not required for production monitoring because polling and the standardized alarm table provide the primary alert/diagnostic path. The generic private trap item stays disabled until real payloads are captured and documented.
